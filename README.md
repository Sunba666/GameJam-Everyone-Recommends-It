# 《大家都推荐》

**21 天 Game Jam · 双人团队 · Unity 2D 客户端 · Windows 可玩版本**

玩家向居民推荐猫、美食、游戏、新闻或音乐，观察兴趣变化、推送疲劳与邻居分享，探索个人选择如何成为公共潮流。

## 项目概况

- **开发环境**：团结引擎 1.10.4 / Unity 2022.3.62t16、C#、uGUI、URP 2D。
- **可玩内容**：9 名住户、5 类主题、12 个阶段、6 种结局，以及本地成就、只读回放和同开局重试。
- **平台进度**：Windows 试玩版本已完成；TapTap 审核已通过（2026-10-19）。
- **流程验证**：2026-10-17 收尾记录包含 108 项流程检查，全部通过；属于项目自带的 PlayMode 场景检查，覆盖阶段推进、结算、回放与重试。详见[收尾交付记录](Design/收尾交付结果_20261017.md)。

## 客户端技术实现

- **纯 C# 玩法模拟**：集中管理居民兴趣、内容饱和度、个体耐受阈值与邻居传播规则。UI 负责提交操作和展示结果，不直接改写模拟数值。
- **可复现的时间与随机**：以 0.1 秒固定步长推进模拟，使用随机种子生成开局；邻居分享采用独立随机流安排时序，支持同开局同操作复现。
- **事件记录与状态快照**：保存推荐、分享和阶段变化后的居民状态深拷贝；回放只读取历史快照，支持逐条浏览和自动播放，不再次执行推荐或随机判定。
- **状态驱动的界面反馈**：状态卡、送达箭头、反应气泡、人物活动与楼层昼夜表现读取真实状态；支持观察暂停、时间加速及当前/历史画面切换。
- **本地进度与开发工具**：PlayerPrefs 保存设置与结局成就；编辑器工具提供增量场景配置、Windows 构建及流程回归检查。

## 核心代码入口

- [ResidentRun.cs](Assets/Scripts/GameFlow/Simulation/ResidentRun.cs)：一局状态、推荐判定、固定步长推进、事件快照与结局计算。
- [ResidentShareSchedule.cs](Assets/Scripts/GameFlow/Simulation/ResidentShareSchedule.cs)：邻居分享的独立随机流与时序调度。
- [ResidentsView.cs](Assets/Scripts/UI/Residents/ResidentsView.cs)：推荐确认、暂停、总结、回放与重试的界面入口。
- [FrontendServices.cs](Assets/Scripts/Core/FrontendServices.cs)：跨场景生命周期、设置、音频与场景切换。
- [ReleasePolishSmokeCheck.cs](Assets/Scripts/Diagnostics/PlayMode/ReleasePolishSmokeCheck.cs)：使用真实场景组件和按钮检查十二阶段、回放边界及存档保护。
- [ReleaseCandidateBuilder.cs](Assets/Editor/BuildTools/ReleaseCandidateBuilder.cs)：沿用已保存场景构建 Windows 候选包，并保留构建结果。

完整模块划分和修改入口见[代码导航](Design/代码导航.md)。

## 运行

- 使用团结引擎 **1.10.4 / 2022.3.62t16**，项目采用 URP 2D、UGUI 和旧输入系统。
- 在 Hub 中添加仓库根目录，打开 `Assets/Scenes/MainMenu.scene`，点击 Play。
- 点击“开始推荐”进入独立的 `Residents.scene`；居民楼内可以返回首页。

## 当前进度

可运行 Demo 已接入随机开局、目标选择、教学推荐、住户观察与确认、每人每阶段一次机会、分散发生的邻居分享、昼夜变化、生活物件、十二阶段结算、只读回放与同开局重试。五组人物动效随偏好切换；主界面、光标、音乐、设置和退出按钮均可用。

居民楼现在为三层各三位住户，共九人。每位住户对五类内容有独立的耐受阈值，新开局生成、阶段间继承；“还喜欢这个主题，却不想再刷推送”的反应来自实际状态。

每阶段 90 秒，玩家通过动作、反应和状态卡观察变化。状态卡采用原图底板，显示五条饱和度、个人临界线及表情；兴趣数值与概率仍隐藏。详见[图解住户状态卡](Design/图解住户状态卡.md)。第 12 阶段最终结算对应六种结局和成就：猫、美食、游戏、新闻、音乐独占第一，或最高人数并列的“势均力敌”。按实际结果解锁，不要求榜首与玩家目标一致；成就保存在本地，重开和退出后保留。详见[六个结局与成就](Design/六个结局与成就.md)。同好临界点加成尚未启用。Windows Demo 位于 `Builds/Windows/Demo`；WebGL 构建需要对应模块。详见[Demo 操作说明](Design/Demo操作与验收.md)。

推荐确认后会出现主题颜色箭头、目标住户提示环和人物右上角的接收图标；仅选择主题和回放不会触发发送。生活物件已按素材比例放大，旧物件与当前物件分层摆放。观察卡、主题按钮及弹窗增加留白，长记录支持滚轮查看。

五类内容有独立送达音效，邻居分享同时显示居民楼与状态图的方向及来源。游戏采用原创合成器循环曲《楼间晚风》，与标题音乐分别播放、切场淡入淡出。顶部“观察 ×1/×2/×4”可减少等待；观察卡保留最近两次接收轨迹，阶段和结尾总结引用真实事件提示因果。音频可由 `Tools/compose_residents_audio.py` 重新生成。

住户活动增加对应的透明伴随动效：刷猫视频时身旁有趴卧猫，301 的真实照顾猫片段改用坐姿猫，听音乐时音符上浮。按当前或历史显示状态对应，不因只选主题而切换；暂停与动态效果开关同步生效。接入与调整见[猫与音符叠加动效](Design/猫与音符叠加动效.md)。

居民楼现使用一张完整背景图，标题与按钮独立于场景，不再拼接顶部或底部图片。夜间材质按图中灯具位置显示暖色照明锥和灯泡光晕，室外偏冷暗、室内和住户保持可辨认；灯光随镜头移动，并按回放记录恢复昼夜。

点击右侧 1F/2F/3F 或上下层按钮，可放大进入该层室内详细场景；“全楼视图”返回居民楼。三层各有一对白天/夜晚背景，夜间保留暖色灯光。仍复用同一批住户、状态、推荐和回放；切层不暂停计时。背景不含住户或主题专属物件，39 个固定互动挂点供后续扩展，详见[室内场景与互动接入说明](Design/楼层室内场景与互动接入说明.md)。

UI 增加内容悬停/按压反馈、纸底反应气泡、明确暂停原因与房号提示；观察卡使用较大固定字号及独立接收轨迹。布局与 HUD 沿用未变化的结果，音量立即生效并合并保存。统一参数在 `Assets/Resources/UIFeedback/Default.asset`，详见[UI 与动效调整说明](Design/UI与动效优化使用说明.md)。

最新一轮补入 301 的猫视频划走与照顾猫反差、约 12 秒的真实传播片段、可切换的行为线索卡，以及 301/202/101 的日常愿望。六结局会展示真实住户名单、旧物与邻居分享来路。选择对象已做同次数、同主题、同时点的原模拟对照，正式规则暂不加全楼三次限制。短场景与验证边界见[七处创意反馈](Design/七处创意反馈与短场景试验.md)。

## 目录

邻居分享会在阶段内不同的虚拟时刻发生，住户右上角用纸质聊天气泡显示实际收到的主题图标；气泡与当前偏好分别显示。分享时机随开局与阶段变化，同开局同操作可以复现。实现与验证见[分散分享说明](Design/分散分享与接收气泡.md)。

- 代码已按核心服务、玩法、场景表现、UI、运行验证与编辑器工具分类。修改功能前可先看[代码导航](Design/代码导航.md)。
- `Assets/`：脚本、场景、预制体及美术音频，保留全部 `.meta` 引用。
- `Packages/`、`ProjectSettings/`：依赖与项目配置。
- `Design/`：玩法方案、工具及[主界面使用说明](Design/主界面与双场景使用说明.md)。
- `ArtConcepts/`：概念图与设计参考。

缓存、本机设置、构建包、历史备份及本地文档临时输出由 `.gitignore` 排除。构建目录不会随 Git 克隆；请使用编辑器构建本地 Windows 版本。
