# 代码导航

当前代码按职责分类。先找功能目录，再找入口脚本；文件夹改变不改变类名、命名空间、组件引用或存档键。运行时代码仍在原来的编译程序集内，未增加程序集定义或额外框架。

## 从哪里开始看

1. `Assets/Scripts/UI/Residents/ResidentsView.cs`：居民楼界面的入口。连接按钮、暂停、推荐确认、阶段总结、只读回放和最终结果。
2. `Assets/Scripts/GameFlow/Simulation/ResidentRun.cs`：真正修改一局状态的地方。推荐机会、兴趣与压力、邻居分享、阶段推进、记录快照和最终排名都在这里。小型数据类 `ResidentState`、`RunEvent`、`SimulationParameters` 与这套模拟放在同一文件。
3. `Assets/Scripts/Core/FrontendServices.cs`：跨场景保留当前局、音频、全局光标、设置、成就及场景切换。

## 目录职责

- `Scripts/Core`：跨场景服务与当前局的生命周期。
- `Scripts/GameFlow/Simulation`：玩法规则、状态和可复现的推进。
- `Scripts/GameFlow/Endings`：六种结局定义、文案配置与本地成就保存。
- `Scripts/Presentation/Building`：整栋楼昼夜表现、楼层放大、楼层配置与互动锚点。
- `Scripts/Presentation/Residents`：住户活动动画及动态效果开关。
- `Scripts/UI/MainMenu`：标题按钮、玩法说明与小人入场。
- `Scripts/UI/Settings`：设置面板、音量即时应用与合并保存。
- `Scripts/UI/Achievements`：成就卡、详情与解锁状态显示。
- `Scripts/UI/Residents`：居民楼操作、观察卡、计时条、开场/总结/回放面板。
- `Scripts/UI/Feedback`：统一动效参数、按钮手感、点击声音、送达箭头调度与反应纸气泡。
- `Scripts/UI/Transitions`：跨场景遮罩转场及弹窗滑入。
- `Scripts/UI/Graphics`：UGUI 原生画出来的圆形、箭头及表情。
- `Scripts/Diagnostics/PlayMode`：开发时的冒烟检查，受 `UNITY_EDITOR` 限制，不作为正式玩家功能编译进包。保留在运行时脚本区，是因为它们需要在 Editor Play 中挂载为组件。
- `Editor/BuildTools`：双场景初始搭建、Windows 构建与本机命令入口。
- `Editor/SceneSetup`：菜单、居民楼、楼层细节、结局及 UI 的安装/修补工具。
- `Editor/Maintenance`：脚本归类迁移和引用检查工具。
- `Tools`：离线素材工具，包括音乐、主题音效及人物与伴随图层的透明序列提取。

## 常见修改入口

- **改推荐规则或耐受度**：修改 `ResidentRun` 的规则实现；调试初值可在 Residents 场景的 `ResidentsView > Simulation` 修改。不要让按钮或动效直接更改兴趣、压力和随机数。
- **改阶段时间**：`ResidentsView` 的 `Stage Duration`、`Total Stages` 和 `Simulation` 的白天/黄昏秒数；`StageProgressView` 只负责显示。
- **改随机分享时机**：`ResidentShareSchedule` 与 `Simulation` 的分享窗口、最小间隔。具体发生时的资格和对象在 `ResidentRun.TryShare`；纸质接收气泡在 `ReceiptBubbleGraphic`，寿命由 `RecommendationDeliveryView` 管理。
- **改推荐操作及暂停条件**：`ResidentsView.SelectTopic`、`ConfirmRecommendation`、`PausedForWorld`。选择主题不发送，确认后才交给 `ResidentRun.Recommend`。
- **改观察卡尺寸/按钮动效**：`Assets/Resources/UIFeedback/Default.asset`；卡片几何修改后停止 Play，运行 `Everyone Recommends > Polish UI And Motion` 更新场景。
- **改楼层画面或放互动道具**：`Assets/Resources/FloorDetails` 的楼层配置、`FloorDetailView` 和 `FloorInteractionAnchor`；接入说明见[楼层室内场景与互动接入说明](楼层室内场景与互动接入说明.md)。
- **改六个结局文案**：`Assets/Resources/Endings/EndingCatalog.asset`。成就 ID 是已保存进度的身份，不随展示顺序变更。
- **改游戏/标题音乐、光标与主题音效**：`Assets/Prefabs/UI/FrontendServices.prefab` 的资源引用和 `FrontendServices`。
- **排查显示问题**：对应 UI/Presentation 组件；排查结果不正确：先看 `ResidentRun.events` 与其状态快照，再看界面呈现。

## 一次推荐的代码路径

点击住户 → `ResidentsView.ShowResident` 打开 `ResidentStatusCard` → `SelectTopic` 仅准备主题 → `ConfirmRecommendation` 调用 `ResidentRun.Recommend` → 记录真实结果 → 界面读取事件，让 `RecommendationDeliveryView`、`ResidentReactionBubble`、`ResidentMotion` 和状态简图显示变化。

回放读取事件的历史快照，只更换显示，不再次调用推荐或随机判定。UI 动效与世界时钟分别处理，设置/观察面板暂停世界的行为由 `ResidentsView` 统一决定。

## 编辑器工具的使用边界

`Everyone Recommends > Code > Validate Script References` 核对本次迁移的脚本内容、.meta、GUID，以及构建场景和预制体的组件引用。记录在 `Builds/Verification/CodeOrganization`。迁移前完整备份在 `Design/DemoBackup_20261008_CodeOrganization`。

`Build Start Menu And Residents Scenes` 是初始搭建工具，会重新创建场景。日常修改现有界面，应使用对应的 SceneSetup 修补工具或直接调 Inspector，不要为了构建试玩包重新搭建场景。Windows 构建沿用独立的 MainMenu 与 Residents。

旧的冒烟脚本保留用于历史问题复查。当前界面与动效主要用 `UIPolishSmokeCheck`，楼层用 `FloorDetailSmokeCheck`，结局用 `EndingsSmokeCheck`；它们是项目自带 Play 检查，不等同于 Unity Test Runner 测试报告。

## 2026-10-11 增量

- CatCareBeatView：单名住户的猫反差，原生 UI 复用已有姿态；只读兴趣、接触压力和生活物件。
- SpreadStoryView：真实事件的 12 秒传播观看片段；独立时钟和场景恢复。
- ResidentLifeStories：三位住户愿望，以及六结局中的真实生活路径。
- CreativeBeatsInstaller：保留旧布局，补齐两信息卡、猫动作与传播面板。
- CreativeInformationTrial / TargetChoiceProbe / RecipientChoiceProbe / CreativeBeatsSmokeCheck：编辑器短场景与诊断，正式构建不包含。
- 状态卡的几何由 IllustratedStatusCardInstaller 与 CreativeBeatsInstaller 控制；Inspector 的 Start With Behaviour Clues 决定默认信息版。

## 猫与音符伴随图层

- `StatePropMotionView`：读取 `ResidentsView.RenderStates` 传入的当前/历史状态，为刷猫视频配趴卧猫、听音乐配上浮音符，为照顾猫片段配坐姿猫。只改变显示，不写入模拟状态。
- `StatePropMotionInstaller`：只补三组 UI 动画与九个住户伴随图层，保留原人物位置、按钮、原动画引用和独立菜单场景。
- `StatePropMotionSmokeCheck`：开发时检查主题对应、历史状态、重复刷新、暂停、减少动效及旧生活物件保留。
- `Tools/import_topic_prop_videos.py`：源 MP4 到固定透明画布的离线转换。接入说明见[猫与音符叠加动效](猫与音符叠加动效.md)。
