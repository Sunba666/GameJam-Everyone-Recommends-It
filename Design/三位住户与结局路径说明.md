# 三位住户与真实结局路径

本轮只补只读描述层。没有修改随机开局、推荐概率、传播、排名、成就条件或生活物件的生成规则。

## 三句日常愿望

- 301 · 阿团：想在窗边照顾一只小猫。
- 202 · 小音：想把一小段旋律练熟。
- 101 · 阿宁：想安静看完一份报纸。

这些话交代住户想做什么。它们不改变开局偏好，不算任务，也不代表已经拥有对应物品或完成了事情。

当下描述读取正式住户状态：活动仍与愿望主题一致时说今天仍在进行该活动；活动改变且旧物件仍在有效期时，指出现在的兴趣和留在房间里的旧用品；喜欢该主题且压力达到个人临界点时，明确表达“活动还在继续，但推送已经看腻”。其他情况只描述正在进行的活动。

## 接线位置

`Assets/Scripts/GameFlow/Endings/ResidentLifeStories.cs` 的静态方法：

- `FocusResidents`：三个重点住户下标 0、4、6。
- `Name(index)`、`FocusLabel(index)`：短名与房号。
- `GetWish(index)`、`GetWishTopic(index)`：愿望与对应主题；其他住户返回空愿望、-1。
- `CurrentLine(run, index, snapshot = null, historicalStage = 0)`：当前描述。回放时传入该事件的 `after` 和 `stage`，避免用现在的阶段判断过去物件是否存在。
- `HasLifeObject(state, topic, stage)`：与场景同样按 `propsUntil > 0 && propsUntil >= stage` 检查真实物件。
- `TopicPathLine(run, topic, snapshot = null, historicalStage = 0)`：该主题继续接触意愿、仍喜欢但过载、活动转向但旧用品留存的房号名单。
- `EndingPathSummary(run, maxKeyEvents = 3)`：六种结局中的真实路径摘要。并列时逐个列出真实领先主题；附玩家推荐数、邻居分享数、最近真实分享来源和接收者、真实活动转向、三位住户的当下状态。

“愿意继续接触”“仍然喜欢”“当前活动”分别读取 `WillingTopic()`、兴趣与个人压力、`preferredTopic`，三种名单可以交叉。不要把最后的继续接触人数直接说成正在做该活动的人数。

## 核验建议

以下是接线后的验收点，不代表已经完成 Unity 运行验证：

1. 读取描述前保存 `Snapshot()` 的全部字段以及完整事件数据；循环读取全部描述后，两者应逐项一致，事件数量不增加。
2. 同一回放快照、同一历史阶段重复读取，文本应相同；跨阶段旧用品过期时，当下描述应消失，过去快照的描述仍应保留。
3. 固定一个仍喜欢猫、正在逗猫且猫压力越线的测试状态，应出现反差描述；降低压力后应恢复普通活动描述。
4. 固定一个活动改为音乐、猫用品仍有效的测试状态，应指出留存猫用品；用品过期后只描述听音乐。
5. 结局全部房号、分享方向与活动转向都应能在当前状态或正式事件中找到证据；并列结局只列最高人数实际并列的主题。

本层不会宣称住户“练完了旋律”“看完了报纸”或“成功照顾了猫”，因为当前模拟没有记录这些完成事实。
