# 新增三组住户动效

来源为素材目录中新加的 `开心吃饭.mp4`、`认真操作.mp4`、`展开报纸.mp4`。每段都是 720×720、121 帧、24 FPS，完整播放约 5.04 秒。源 MP4 保持原样。

## 游戏内的表现

- 开心吃饭：当前活动为美食，最近收到的是美食且真实反应为开心，同时尚未超过个人饱和阈值时使用。
- 认真操作：当前活动为游戏、确实感兴趣且未超过个人饱和阈值时使用。
- 展开报纸：当前活动为新闻、确实感兴趣且未超过个人饱和阈值时使用。视频首尾都是已经展开的报纸，按阅读小动作循环，没有反复从零展开的额外流程。
- 其他情况下保留原五组基础动画。喜欢猫但划走视频的重点住户仍使用原有照顾猫的反差表现。

只改变人物 Image 的图片序列。场景人物的位置、大小、缩放、按钮点击范围不变；头像读取当前人物图片。世界暂停时动画一起暂停，关闭“动态效果”时使用对应新动作的首帧静图。只读回放传入历史快照来选择动作，不读取当前结果冒充历史。

## 素材和代码

新增文件位于 `Assets/EveryoneRecommends/ResidentMotion/Variants` 的 `FoodHappy`、`GameFocused`、`NewsUnfold` 子目录，均含透明 PNG 序列、UI AnimationClip 和 AnimatorController。原五组帧、动画、控制器和 `.meta` 保留。

视频白底只从画面外侧连通区域移除，身体和报纸里的浅色区域保留。外沿做白底去色；之后整组采用固定的等比缩放和位移，放在 960×960 透明画布内，与原动作脚底位置和视觉高度对齐。没有逐帧追踪缩放，也没有重绘人物。Unity 最大导入尺寸为 256，双线性、无 Mipmap、RGBA，控制运行时纹理用量。

- `ResidentMotion.cs`：可选新动作及状态判断；缺少新增素材时退回基础动画。
- `ResidentsView.RenderStates()`：传入当前或历史 ResidentState。
- `ResidentMotionAdditionsInstaller.cs`：编辑器菜单 `Everyone Recommends → Install Resident Motion Additions`，只补接新动作，保存前备份，不重建 UI。
- `Tools/import_resident_motion_videos.py`：从原视频重新提取透明帧并放在验证目录，之后由安装工具生成 Unity 动画。

转换记录与五帧检查图位于 `Builds/Verification/NewResidentMotion`；Unity 安装和运行检查记录位于 `Builds/Verification/ResidentMotionAdditions`。运行检查中的边界条件使用状态副本，不修改正式存档，也不把测试用开心反应写进真实游戏。

本轮修改前备份：`Design/DemoBackup_20261014_ResidentMotionAdditions`。安装器还会另存当时的场景与未保存场景副本。

## 已完成验证

最终一轮 Play 检查为 52 项通过，包含三组实际图片序列推进、121 帧及实际循环时长、厌烦边界和错误主题回退、重复刷新不重置、世界暂停、状态卡同步、关闭动态效果与存档不变。额外检查了压力自行达到临界点和自行回落时，不需要新事件或重新推荐也能切换合适动作；美食的过载反应不会因压力恢复而被伪造成开心。最初发现的多余循环终点帧已修正；初次失败记录另存保留，最终结果在 `ResidentMotionAdditions/Checks.txt`。

编辑器中的实际鼠标流程已走过目标选择、点击 202、选择游戏、确认一次教学推荐、手动开始阶段。随机开局中的游戏和新闻新动作可见，状态卡头像与场景一致；教学真实结果为“看得很开心”。这次编辑器随机开局没有美食住户，开心吃饭的全部触发边界由状态副本验证，没有修改自然开局以制造开心。

最终 Windows 包另行启动验证：自然开局 301 正在吃饭，选择美食目标后向 301 确认了一次美食推荐。真实结果为“看得很开心，想再了解一点”，场景立即切到新“开心吃饭”动作；手动开始阶段后图片序列继续播放，再点击人物时头像与实际动作同步、计时暂停。对应截图为 `ResidentMotionAdditions/Standalone_FoodHappy_RealRecommendation.jpg`、`Standalone_FoodHappy_StatusCard.jpg`。本次只检验新增动效相关流程，不代表完整十二阶段通关。
