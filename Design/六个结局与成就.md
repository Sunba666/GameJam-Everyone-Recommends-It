# 六个结局与六个成就

本次以一局的第 12 阶段最终结算为触发点。每局只有一个结局，成就累计保存在本机。阶段总结不是结局。

## 六种结果

- 猫咪当家：猫的最终人数独占第一。
- 美食当道：美食的最终人数独占第一。
- 再来一局：游戏的最终人数独占第一。
- 全楼头条：新闻的最终人数独占第一。
- 同一首歌：音乐的最终人数独占第一。
- 势均力敌：最高人数并列，没有唯一榜首。

人数使用原有真实继续接触意愿统计，会考虑兴趣和接触压力。当前活动图片、单阶段推荐次数或玩家选定目标，都不能代替这个结果。

“势均力敌”允许两类或多类内容并列第一。例如 3、3、2、1、0；不要求五类一样多。九位住户无法平均分到五类。4、2、2、1、0 是猫独占第一，第二名的并列不会触发此结局。

结局依据实际结果，目标依据开局选择，分别显示。即使没有完成猫目标，音乐独占第一也会解锁“同一首歌”。这使换话题、停止单推或主动维持均衡能够留下不同的收集结果；功能实现不等于这些策略的可达性与平衡已完成真人盲测。

## 保存与界面

第 12 阶段正常结算后立即保存；不必再点一次“查看最终结果”。打开结局、进入或退出回放、返回同一个结果页不会重复解锁。

主界面现有六张成就卡片显示主题图标、名称、条件、未解锁或已解锁状态。点击卡片查看说明，返回和关闭继续可用。锁定卡片的点击只是查看，不会解锁。

保存采用独立 PlayerPrefs 键 `EveryoneRecommends.EndingAchievements.v1`，只存六个解锁标记，与音量、全屏设置及开局种子分开。同开局再试、新随机开局和程序重新启动保留成就。不新增养成奖励、道具或联网账号。

## 开发修改

六种名称、文本、颜色和图标配置在 `Assets/Resources/Endings/EndingCatalog.asset`。在 Inspector 编辑即可。固定 ID：Cat=0、Food=1、Game=2、News=3、Music=4、Balanced=5；修改显示名称不会丢失成就，修改 ID 会改变存档含义。

`ResidentRun.Ending()` 读取最终正式状态并确定结果；`FrontendServices.CollectFinishedEnding()` 每局只收集一次；`EndingAchievements` 保存本地进度；`AchievementsView` 和 `AchievementCardView` 呈现现有卡片。

菜单 `Everyone Recommends > Install Six Endings And Achievements` 仅修补引用和卡片。已有结局配置保留，修改前自动备份两场景。完整接入前备份在 `Design/DemoBackup_20261008_Endings`。

## 验证方式

专项 Play-mode 检查与截图位于 `Builds/Verification/Endings`。使用独立临时存档验证六种定向最终状态、最高并列、非榜首并列、压力影响、目标与结局分离、重复回放、重开及跨场景卡片状态；结束后清理临时键并恢复原成就存档。

标题带 `Fixture` 或 `TestStore` 的截图用于展示定向测试，不代表真人已经游玩收集全部成就。真实操作、构建与运行日志另行记录。

2026-10-08：42 项专项 Play-mode 检查通过。正常规则下以 16 个开局种子、7 种推荐/停推策略进行 112 局采样，观察到六种结果全部出现；没有直接改住户状态或调整模拟参数。记录在 `StrategySamples.json`，属于规则可达性检查，不代表真人收集难度已平衡。验证使用临时保存键，检查确认原成就进度未被修改。
